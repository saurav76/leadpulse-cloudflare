# Security Policy

LeadPulse is an early-stage pilot. The public repository and demo are not a certification of production readiness.

## Supported versions

No stable security-maintenance branch has been declared. Security fixes will be assessed for the current default branch.

## Reporting a vulnerability

Please avoid publishing vulnerabilities, proof-of-concept exploits, credentials, or personal data in public issues or pull requests.

If GitHub's **Report a vulnerability** option is available on the repository's Security tab, use it to send a private report. Otherwise, contact the repository owner privately through an established channel before sharing details. Do not post exploit details publicly while arranging a secure channel.

Include a short impact summary, affected component, and safe reproduction steps with secrets and customer data removed.

## Security boundaries

- Only monitor sites for which you have explicit permission and verified domain ownership.
- Never submit real enquiry forms during presence checks.
- Review URL and DNS handling, redirects, rate limits, and authorization before enabling monitoring.
- Keep deployment credentials in provider-managed secrets, never in committed source.
- Consult the README's production-readiness limitations before deploying.
